# Choose a review mode

The tool has two modes. Use batch when you already know which files belong in the review. Use OpenCode when an agent needs to search the repository for supporting evidence.

<ReviewModeCards />

## Batch

Batch collects the selected Markdown files and sends them together in one structured request. It has little orchestration and works well when the whole corpus fits comfortably in the model's context.

```bash
GEMINI_API_KEY=<gemini-key> go run . batch examples/offsite
```

As the corpus grows, unrelated material can crowd out details that matter. Choose a smaller set of files or use OpenCode for a repository-wide investigation.

## OpenCode

OpenCode connects to a running local server, creates a review session, and gives the agent read-only repository tools. The agent can search and inspect evidence before returning findings in the review schema. Start the server with `just opencode-server` in one terminal, then run the review command in another.

```bash
opencode auth login
go run . opencode \
  -model opencode-go/kimi-k3 \
  -url http://127.0.0.1:4097 \
  -timeout 8m \
  -verbose \
  examples/offsite/research.md
```

OpenCode can follow relevant leads that were not selected in advance. Its runtime and token use vary with the search path. The review prompt recommends limits, while the agent decides which read-only tools to use.

## Images

Image handling is shared preprocessing for review. Local transcriptions are cached by path and content hash.

<ImagePipeline />

- SVG source is transcribed as text.
- PNG, JPEG and WebP use the configured vision path.
- Remote HTTP(S) images are deferred.

## Structured output

Both modes return the same review result shape. Batch uses the LiteLLM configuration; OpenCode asks the selected provider for JSON Schema output and validates the structured result. Provider routes can differ in their support for schema-constrained output, so use a provider tested with this mode.

For the measured OpenCode provider results and implementation history, see [ADR 0007](/appendix/decisions/0007-review-modes-and-defect-coverage).
