# Reader failures

The goal is to catch documentation that passes the build but still fails the reader.

A build can prove that files exist, Markdown compiled, and the site emitted HTML. It cannot prove
that the rendered page is useful, truthful, or readable. This reviewer fills that gap by checking
the page a visitor actually sees.

## Why This Tool Exists

Most docs tooling stops too early. Link checkers catch dead URLs. Build tools catch invalid syntax.
Neither one can say, "the screenshot below contradicts the sentence above" or "this diagram compiled
as text instead of rendering as a diagram."

The reviewer should be cheap where certainty is possible and careful where judgment is needed:

| Check | Best tool | Result |
|---|---|---|
| Internal links, anchors, missing images, obvious dead URLs | Mechanical check | Blocking finding |
| Soft-404 pages, unclear acronyms, stale references | Text extraction plus model judgment where needed | Report finding |
| Broken diagrams, unreadable layout, screenshot/text mismatch | Browser screenshots plus vision judgment | Report finding |
