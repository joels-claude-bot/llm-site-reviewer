# Docs review 2026-06-29

Scope: full-site structure sweep plus a focused visual and content review of the new
[ADR 0001](/appendix/decisions/0001-test-and-corpus-strategy). External links checked: none broken.

## Project structure

FIRST_IMPRESSION: a tool that finds "reader failures" in a documentation site, described through a
spec, a design approach, a landscape, and a testing strategy. Read correctly from nav alone.

GAPS: no install, usage, configuration, or troubleshooting pages. Expected for now, the tool is not
built yet and the site is spec and design only. Worth revisiting once code exists.

ACRONYMS: `ADR` unexpanded on the decisions page (actionable). `CI` and `LLM` unexpanded in
`appendix/lessons-learned` and `appendix/exit-codes` (appendix is out of review scope, leaving as is).

ASSUMED: `L2`/`L3` in `concept/approach` read as assumed from headings alone, but the ladder diagram
on that page defines them, so this is a false flag from a headings-only scan. `corpus` and
`recall/precision` are defined where they are used.

## ADR 0001 visual pass

RENDERS, LEGIBLE, COLOUR, HIERARCHY, DENSITY, TRUNCATED: all OK. The four diagrams render as
diagrams (not raw source), text inside them is readable at width, callouts are colour-coded.

OPACITY (the real flag): on a cold read the page never says what "the reviewer" is or what it
reviews. The first diagram's "Corpus run" node and the term "the reviewer" are unanchored, and
`Finding` is used in code before it is described. First unanswered question: "what is the reviewer
and what does it analyse?"

## ADR 0001 content pass

WHAT_WHY: present for the testing decision itself, but it assumes you already know the product.

ACRONYMS: `ADR`, `MDX` unexpanded.

ASSUMED: project-specific terms worth fixing are `reviewer`, `corpus`, `ADR`. The remaining flags
(`pytest`, `JSON`, `assertion`, `smoke test`, `prompt`, `parser`, `slice`) are standard engineering
vocabulary and correct for an ADR's audience; dismissed.

DOES_NOT: present and good (rules out the one-big-LLM-pass, says what snapshots are not, says what the
matching does not yet do).

SIMPLER: the "Runnable examples" section could compress its two uses, minor.

## Actions taken

Fixed the cold-read opacity immediately, since it was flagged by every pass:

- Added an orienting opener naming the reviewer and what it does, linking to the problem and approach.
- Expanded `ADR` (Architecture Decision Record) and glossed `corpus` on first use.
- Added a one-line gloss of `Finding` at its first appearance.

Not actioned: the structural GAPS (premature, no tool yet) and the generic-vocabulary ASSUMED flags.
